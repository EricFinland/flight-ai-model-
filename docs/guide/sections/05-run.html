Quickstart

Each released model file is about 17 MB and runs on any CPU. Clone, install, and you can talk to Prewright in a minute.
git clone https://github.com/EricFinland/flight-ai-model- && cd flight-ai-model-
pip install -e .

python3 scripts/chat.py --model checkpoints/main_chat.pt                      # talk to it
python3 scripts/generate.py --model checkpoints/main.pt    --prompt "A balloon is" --seed 0
python3 scripts/generate.py --model checkpoints/control.pt --prompt "A balloon is" --seed 0

main_chat.pt is the one to talk to. main.pt (flight-free) and control.pt (same books, flight kept) are base models: they only continue text. Running generate.py on both with the same prompt and seed is the quickest way to see the difference the scrub makes.

Expectation. This is an 8.5M-parameter model trained on 13.9M tokens. Expect period-flavoured prose that wanders, not a capable assistant.

The Makefile wraps the same calls: make chat, and make generate PROMPT="..." to complete a prompt with both base models.

Reproduce from scratch

Every step runs from the repository root. Raw data and built corpora live outside git, in /home/user/data by default; override with DATA=. Timings are for a shared 4-core CPU.

pip install -e '.[dev]'
make download corpus rescrub tokenizer tokenize
make train
make sft-data finish
  1. Downloadmake download fetches the PG-19 books published in or before 1902 (about 6.8 GB, 17,350 files). Needs curl and gsutil.
  2. Build the corporamake corpus applies the date, anachronism, English and flight filters to produce the main (flight-free) and control corpora. About 16 min.
  3. Rescrubmake rescrub re-derives main from control with the current lexicon, without re-downloading. About 11 min. Run it once after a fresh build to match the released corpus, and after any change to src/prewright/flight.py.
  4. Tokenizermake tokenizer trains a byte-level BPE with 8,192 tokens on about 300 MB of main training text only. 2 to 5 min.
  5. Tokenizemake tokenize writes token files with the same books in the same order for both corpora, capped at 150M training tokens. About 15 min.
  6. Trainmake train trains main and control in parallel, 2 threads each, 850 steps. About 3 to 3.6 h. Resumable: re-run the command after a crash. Deterministic given the seed, so both models see text from the same positions.
  7. Chat datamake sft-data mines question-and-answer pairs from the scrubbed books. About 18 min.
  8. Finishmake finish runs, in order: fp16 exports (about 17 MB each), a chat fine-tune of each model on the same pairs (2 epochs, at most 40 min each), the main-versus-control evaluation (about 30 min), the side-by-side chat showcase, the flight-gap curve over training, and the fill of results into the README and model card.

Paths and settings are Make variables, for example make tokenize DATA=/mnt/data WORKERS=16 MAX_TRAIN_TOKENS=0. make help lists every target. The long form with the underlying script commands is docs/reproduce.md. Run make test for the unit tests, and make smoke to exercise the evaluation pipeline on a fake model.

Main and control must always use the same config and the same step count, or the comparison means nothing. On a different machine, measure tok_per_s in log.jsonl after a few minutes and pick --max-steps so both runs fit your budget.

Scaling up on GPUs

Two GPU configs are provided. They have not been run on a GPU yet: the build machine had none. The CUDA path was reviewed and the multi-GPU path is tested on CPU, but expect to fix something small the first time.

Cost for both models (main and control), on-demand rental: about $10 to $25 for 125M, and about $250 to $500 for 1B. Start with 125M; it exercises the whole setup cheaply.

make train-gpu DATA=$DATA CONFIG=configs/gpu_125m.yaml
make train-gpu DATA=$DATA CONFIG=configs/gpu_1b.yaml NPROC=8
  • Build the data with no token cap: make tokenize MAX_TRAIN_TOKENS=0. The full main corpus is about 1.7B tokens.
  • Run the short smoke tests first (tiny config, then 30 steps of the real one) to check speed and memory.
  • Out of memory: halve micro_batch and double grad_accum. Tokens per step stay the same.
  • The corpus is the limit. 125M sees about 1.5 passes; 1B sees about 5, already at the edge of useful repetition. Do not train the 1B model longer; it needs more pre-1903 text.
  • Single machine only. No multi-node, FSDP or gradient checkpointing. Full guide: docs/scaling.md.

FAQ

Why 1902?

The Wright brothers first flew in December 1903. Books dated 1902 or earlier cannot describe powered flight as a fact. Dates are catalogue dates and can be wrong, so an anachronism filter catches the obvious misdated cases.

Why a control model?

The control trains on the same books in the same order, with the same architecture, seed and steps, but with flight text kept. Any difference between the two is then due to the scrub, not to the data volume, the setup or luck.

Does it know birds fly?

It can. Birds, bats and insects flying are deliberately kept, along with flights of stairs, flying fish, kites and myth such as Icarus. Only human flight as technology is removed.

Can it infer flight?

That is the question the evaluation asks. Inference is left possible on purpose: the model has birds, kites, and "lighter than air" as plain chemistry. The comparison with the control measures how far apart they end up.

Why is the output nonsense?

The model has 8.5M parameters and saw 13.9M tokens on a CPU. It picks up period style and vocabulary but not coherent reasoning. The GPU configs scale this up.

Where is the data?

Not in git. Raw books and built corpora live in /home/user/data and are rebuilt from the public PG-19 collection by make download corpus. Only the tokenizer and the roughly 17 MB model files are committed.
